# Feature Specification: 常駐デスクトップ時計ウィジェット

**Feature Branch**: `001-clock-widget`

**Created**: 2026-09-17

**Status**: Draft

**Input**: User description: "Windows 11 上で動作する常駐型のデスクトップ時計アプリ。時刻/日付/曜日を表示し、フォント・文字色・背景透過度をカスタマイズ可能。ドラッグ配置と位置ロック、最前面表示の ON/OFF。モニタごとに表示/非表示と表示位置を独立管理。設定は JSON ファイルで保存(レジストリ不使用)。Windows 起動時に自動起動。右クリックメニューでのクイック切替と、別ウィンドウでの詳細設定。"
(詳細は `docs/requirements.md` を参照)

### Session 2026-09-28 (モニタの見分け方の補足、issue #52)

- Q: 設定を新しい見分け方に移した後、以前のバージョンに戻したとき、モニタごとの表示位置は保たれる
  必要があるか? → A: 保つ必要はない。以前のバージョンに戻すと、モニタごとの設定は初期値に戻ってよい
  (Assumptions)
  - 以前のバージョンに戻すのは普段の操作ではなく、constitution の品質の線引きで気にしない側に入るため
  - 古い形の設定も残す案は、同じモニタの設定が 2 つ並び、どちらが正しいか分かりにくくなるため不採用とした
  - 補足 (`/speckit-analyze` の 2 回目): その後の plan で、設定ファイルの形を変えない設計にした
    (research.md #20)。そのため実際には以前のバージョンでも設定をそのまま読めるが、保証はしない、
    という上の決定は変えない
- Q: 同じ型番のモニタが複数あり、端子が変わったなどで、どの設定を使うべきか決められない場合は
  どうするか? → A: その型番の設定のうち、接続中のどのモニタにも使われていないものを、端子の番号順に
  割り当てる (FR-040、Edge Cases)
  - 同じ型番のモニタを 2 台並べる構成はよくあり、机のレイアウトの変更や引越しで別の端子につなぎ直す
    ことも十分ありうる (人間の指摘)。なので、まれな場合として諦めず、引き継げるようにする
  - 割り当てが外れても、左右が入れ替わる程度で済み、初期値に戻るよりは設定し直す手間が少ない
  - 「つないだ順に割り当てる」は人間の提案。つないだ順は記録していないため、端子の番号順にした
  - 当初 (specify・clarify の時点) は「どの設定を使うべきか決められないので、新しいモニタとして扱う」
    としていたが、この決定で置き換えた。同じ型番の設定が一度 2 つになると、以後ずっと引き継げなくなる
    という問題 (`/speckit-analyze` の 3 回目の指摘 M1) も、この決定で解消する

### Session 2026-09-27 (モニタの見分け方、issue #52)

- 外部の AI によるレビューで、モニタを見分ける ID に接続端子の情報が含まれていると指摘された
  - 同じモニタでも、ケーブルを別の端子につなぎ直すと別のモニタとして扱われ、設定が初期値に戻る
  - research.md #2 は「物理モニタに紐づき、再接続後も安定する」としており、実装と食い違っていた
  - それまでの Assumptions は「同一モニタとして認識できる範囲で維持される想定」とぼかしていた
- Q: モニタをどう見分けるか? → A: モニタのメーカーと型番で見分ける。同じ型番のモニタが同時に
  複数つながっている間だけ、つないでいる端子でも見分ける (FR-040)
  - 型番が違うモニタは、どの端子につなぎ直しても前の設定を引き継ぐ
  - 同じ型番の別の個体に買い替えた場合に設定が引き継がれるのも、望ましい動きとして扱う
  - モニタ個体のシリアル番号で見分ける案は不採用とした
    - 手元のモニタの 1 台 (SONY の TV) はシリアル番号がダミー値で、個体を見分けられなかったため
    - 同じ型番のモニタを左右で入れ替えた場合、利用者が気にするのは「左の画面の設定」であり、
      個体ごとに設定を追いかける意味が薄いため
- Q: 既存の設定ファイルに保存されたモニタごとの設定はどうするか? → A: 新しい見分け方に引き継ぎ、
  アップデートしても表示/非表示・表示位置が変わらないようにする (FR-040)
  - 既存の設定ファイルには、メーカーと型番を含む形でモニタが記録されているため、そこから引き継げる
- 同じ型番のモニタの台数が変わったときの扱いは、通常の操作ではまず起きないため、Claude が次のように
  決めた (Edge Cases)
  - 1 台から 2 台に増えたら、前と同じ端子につながっている方が前の設定を引き継ぎ、もう 1 台は新しい
    モニタとして扱う
  - 2 台から 1 台に減ったら、残った 1 台は前と同じ端子の設定を使う

### Session 2026-09-26 (自由配置のときの余白の扱い、issue #43)

- issue #39 の実機確認で、右クリックメニューの「配置 ▶ 余白」について次の 2 点に違和感があった
  - アンカー指定のウィジェットをドラッグして自由配置にしても、余白のチェックが外れない
  - 自由配置のまま作業領域の端にぴったり付けた状態で余白を選んでも、余白が入らない (動かない)
- どちらも issue #26 で決めたとおりの動きだった。余白は自由配置の間も値とチェックを残し、選んでも
  値を保存するだけでウィジェットは動かさない、としていた
- issue #39 の clarify で「ドラッグしたら横位置・縦位置のチェックを外す」と決めた際に、同じ「配置」
  メニューに並ぶ余白との一貫性を確かめていなかったことが、違和感の原因と見ている
- Q: ドラッグで自由配置になったとき、余白のチェックはどう見せるか? → A: 横位置・縦位置と同じく
  チェックを外す (FR-035)
  - 「自由配置なら、配置メニューのどこにもチェックが付かない」とそろえるため
  - 余白の値そのものは残し、次にアンカー指定したときに使う
  - チェックを残したままグレーアウトする案は、横位置・縦位置と見え方がそろわないため不採用とした
- Q: 自由配置の間に余白を選んだら、どうするか? → A: 作業領域の縁までの距離がその余白以下の縁から、
  選んだ余白ぶん内側へ離す。どの縁もその余白より離れていれば、その余白の項目はグレーアウトする (FR-039)
  - 端にぴったり付けたウィジェットに余白を入れたい、という元の要望にそのまま応えるため
  - 範囲内の縁が 2 つ (隅の近く) なら、両方の縁から離す。片側だけ離れると隅に置いたときに不自然なため
  - 次の案は不採用とした
    - 横位置・縦位置と同じく、両方の軸を今の位置から一番近いものにしてアンカー指定する案。選んでいない
      方の軸まで動いてしまうため (例: 右端の中ほどより上にあるウィジェットが、縦方向の中央へ動く)
    - 一番近い隅にアンカー指定する案。画面の中ほどにあるウィジェットが隅まで飛び、驚きやすいため
    - 自由配置の間は余白の項目を常にグレーアウトする案。端に付けたまま余白を入れる手段がなくなるため
- Q: 余白を入れて動かした後は、アンカー指定にするか? → A: しない。自由配置のまま位置だけ動かし、
  余白のチェックも付けない
  - 「自由配置の間の余白は、縁から少し離すための操作」と一言で説明できるようにするため
  - 範囲内の縁が 2 つのときだけその隅にアンカー指定する案は、同じ操作なのにチェックが付くときと
    付かないときがあり分かりにくいため不採用とした
  - 自由配置のままなので、その後にウィジェットの表示サイズが変わっても縁との間隔は保たない。間隔を
    保ちたい場合は、横位置・縦位置を選んでアンカー指定にすればよい
- Q: ウィジェットが大きく、向かい合う 2 つの縁 (左と右、または上と下) の両方が余白の範囲内にある
  ときに余白を選んだら、どうするか? → A: 特別なルールは決めず、本 issue の範囲外とする (Assumptions)
  - 高 DPI の小さめの画面でフォントを最大にするなど、ウィジェットが作業領域とほぼ同じ大きさになった
    ときだけ起こる
  - そもそもウィジェットが作業領域に対して大きくなりすぎる設定ができること自体を見直すべきで、
    issue #45 として切り出した。そちらで余白との関係もあわせて検討する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - デスクトップに時計を常時表示する (Priority: P1)

ユーザーは PC にログインすると、何も操作しなくてもデスクトップ上に現在時刻が表示された時計ウィジェットが現れ、常駐し続ける。既存の Microsoft Store ウィジェットでは満足できなかったため、これが本アプリの中核価値である。

**Why this priority**: これがなければアプリの存在意義がない。他のすべての機能は、この基本表示の上に成り立つ。

**Independent Test**: アプリをインストールし PC を再起動するだけで、ログイン後にデスクトップに時計が表示され、時刻が 1 秒単位で正しく更新されることを確認できる。

**Acceptance Scenarios**:

1. **Given** アプリがインストールされ自動起動が有効, **When** Windows にログインする, **Then** デスクトップ上に時計ウィジェットが自動的に表示される
2. **Given** 時計ウィジェットが表示されている, **When** 時間が経過する, **Then** 表示されている時刻が実際の時刻と一致し続ける
3. **Given** 時計ウィジェットが表示されている, **When** ユーザーが日付・曜日の表示を ON にする, **Then** 時刻に加えて日付と曜日が表示される
4. **Given** タスクトレイの常駐アイコンを右クリックしている, **When** 自動起動を OFF にする, **Then** 次回 Windows 起動時にウィジェットは自動的に表示されなくなる

### User Story 2 - 見た目を自分好みにカスタマイズする (Priority: P2)

ユーザーはフォントの種類・サイズ・文字色、および背景の透過度を自分の好みやデスクトップの壁紙に合わせて調整できる。

**Why this priority**: 既存ウィジェットへの不満が「見た目が自分の好みに合わない」ことに起因しているため、カスタマイズ性は本アプリの主要な差別化価値である。基本表示(P1)の次に重要。

**Independent Test**: 詳細設定画面でフォント・サイズ・色・透過度を変更し、即座にウィジェットの見た目に反映されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 詳細設定画面を開いている, **When** フォント種類・サイズ・文字色を変更する, **Then** 時計ウィジェットの表示が変更内容を即座に反映する
2. **Given** 詳細設定画面を開いている, **When** 背景透過度を 0〜100%の範囲でスライダー操作する, **Then** ウィジェットの背景の透け具合がリアルタイムに変化する
3. **Given** 見た目をカスタマイズした後, **When** アプリを再起動する, **Then** カスタマイズした見た目が保持されている
4. **Given** 詳細設定画面を開いている, **When** 秒表示の ON/OFF、時刻表示と日付/曜日表示それぞれのフォントサイズ・文字色、日付の区切り文字、曜日の表示形式、時刻に対する日付/曜日表示の位置(上/下/左/右)を変更する, **Then** 時計ウィジェットの表示が変更内容を即座に反映する
5. **Given** 日付表示と曜日表示がともに ON になっている, **When** 時計ウィジェットを表示する, **Then** 日付と曜日は改行されず同一行に表示される
6. **Given** アプリを終了し、設定ファイルで、あるモニタの日付の区切り文字を選択肢にない文字 (例: `🍣`) に書き換えた, **When** アプリを起動して、詳細設定画面でそのモニタを選ぶ, **Then** そのモニタの日付はその文字で区切って表示され (例: `2026🍣09🍣28`)、詳細設定画面の区切り文字の欄は、どの選択肢も選ばれていない空欄として表示される。画面を開いただけでは、設定ファイルの区切り文字は変わらない (英数字以外の文字は、アプリの起動や保存で書き出されると `\uXXXX` の形で書き出されることがあるが、同じ文字を表す)

### User Story 3 - 配置を自由に決め、誤操作から保護する (Priority: P2)

ユーザーはウィジェットをドラッグしてデスクトップ上の好きな位置に配置し、位置が決まったら「ロック」して、以後の誤操作（うっかりドラッグ）による位置ズレを防ぐ。また、常に最前面に表示するかどうかを切り替えられる。

**Why this priority**: 配置の自由度と、それを維持する安心感(誤操作防止)は、常駐ツールとして日常的に使う上での基本的な使用感を左右する。

**Independent Test**: ウィジェットをドラッグして移動できること、ロック後はドラッグしても位置が変わらないこと、右クリックメニューから最前面表示を ON/OFF できることを個別に確認できる。

**Acceptance Scenarios**:

1. **Given** 位置ロックが無効な状態, **When** ウィジェットをドラッグする, **Then** ウィジェットは新しい位置に移動する
2. **Given** 位置ロックが有効な状態, **When** ウィジェットをドラッグしようとする, **Then** ウィジェットの位置は変化しない
3. **Given** 右クリックメニューを開いている, **When** 「位置ロック」を選択する, **Then** ロックの有効/無効が切り替わる
4. **Given** 右クリックメニューを開いている, **When** 「最前面表示」を選択する, **Then** 他のウィンドウより手前に表示されるかどうかが切り替わる
5. **Given** 位置ロック・最前面表示を設定した状態, **When** アプリを再起動する, **Then** 位置ロック・最前面表示の設定がそれぞれ保持されている
6. **Given** 右クリックメニューを開いている, **When** 「終了」を選択する, **Then** アプリケーションが終了し時計ウィジェットが閉じる
7. **Given** 「最前面表示」が無効な状態でウィジェットが他のウィンドウの背後に隠れている, **When** タスクトレイの常駐アイコンをクリックする, **Then** すべての時計ウィジェットが最前面に呼び戻される
8. **Given** タスクトレイの常駐アイコンを右クリックしている, **When** 「終了」を選択する, **Then** アプリケーションが終了し時計ウィジェットが閉じる
9. **Given** 位置ロックが無効な状態でウィジェット本体の右クリックメニューを開いている, **When** 横位置(左/中央/右)・縦位置(上/中央/下)の組み合わせと余白(狭め/広め)を選択する, **Then** そのモニタのウィジェットは指定した位置へ移動し、以後その位置関係を維持する
10. **Given** 位置ロックが有効な状態, **When** ウィジェット本体の右クリックメニューを開く, **Then** アンカーの項目は表示されているがグレーアウトしており選択できず、ウィジェットの位置は変化しない
11. **Given** アンカー指定で配置されたウィジェット, **When** ユーザーがそのウィジェットをドラッグする, **Then** 以後はドラッグ後の座標が使用され、そのモニタのアンカー指定は解除される
12. **Given** アンカー指定で配置されたウィジェット, **When** DPI スケールの変更やフォントサイズの変更でウィジェット自体の表示サイズが変わる, **Then** 指定した位置関係(隅寄せ等の見た目)は崩れず維持される
13. **Given** タスクトレイの常駐アイコンを右クリックしている, **When** 「詳細設定」を選択する, **Then** 詳細設定画面が、プライマリモニタを編集する状態で開く (FR-042)
14. **Given** タスクトレイの常駐アイコンを右クリックしている, **When** メニューを見る, **Then** 「詳細設定」「自動起動」「終了」だけが表示され、位置ロック・最前面表示・配置の項目はない。「自動起動」には、今の ON/OFF がチェックで表示されている (これらはウィジェット本体の右クリックメニューで、そのモニタについて切り替える。FR-038)
15. **Given** 位置ロックが無効な状態, **When** ウィジェットを隣のモニタとの境界やタスクバーの方へドラッグし続ける, **Then** ウィジェットは表示中のモニタの作業領域の端で止まり、はみ出したり別のモニタへ移ったりせず、揺れることもない。マウスを離すと、止まった位置がそのモニタの表示位置として保存される
16. **Given** アンカー指定で配置されたウィジェット, **When** ユーザーがそのウィジェットをドラッグした後に右クリックメニューの「配置」を開く, **Then** 横位置・縦位置・余白のいずれの項目にもチェックが付いていない
17. **Given** 位置ロックが無効で、自由配置のウィジェットが作業領域の縁に接している (または縁までの距離が選ぶ余白以下である), **When** 右クリックメニューから余白 (狭め/広め) を選択する, **Then** ウィジェットはその縁から選んだ余白ぶん内側へ移動する。範囲内の縁が 2 つ (隅の近く) なら両方の縁から離れる。移動後も自由配置のままで、横位置・縦位置・余白のいずれにもチェックは付かない
18. **Given** 位置ロックが無効で、自由配置のウィジェットがどの縁からも「狭め」の余白より離れている, **When** ウィジェット本体の右クリックメニューの「余白」を開く, **Then** 「狭め」の項目はグレーアウトしており選択できない。「広め」についても、どの縁からも「広め」の余白より離れていればグレーアウトしている

### User Story 4 - マルチモニタ環境でモニタごとに管理する (Priority: P3)

複数モニタを使うユーザーは、モニタごとに時計ウィジェットを表示するかどうかを選び、表示するモニタごとに異なる位置・見た目 (表示内容・フォント・レイアウト・背景)・位置ロック・最前面表示を独立して保持できる。

**Why this priority**: マルチモニタ環境は一部のユーザーのみが持つ構成であり、単一モニタでの基本価値(P1-P3)が満たされていれば製品として成立するため、優先度は相対的に低い。

**Independent Test**: 2 台以上のモニタ環境で、モニタ A のみ表示・モニタ B は非表示に設定し、モニタ A での表示位置を移動した後、アプリを再起動してもモニタごとの表示/非表示と位置がそれぞれ保持されていることを確認できる。さらに、モニタ A とモニタ B で見た目・位置ロック・最前面表示を変え、片方の変更がもう片方に影響しないことと、再起動後もそれぞれ保持されていることを確認できる。

**Acceptance Scenarios**:

1. **Given** 2 台以上のモニタが接続されている, **When** 詳細設定でモニタ B の表示を OFF にする, **Then** モニタ B には時計ウィジェットが表示されなくなり、モニタ A の表示には影響しない
2. **Given** モニタ A とモニタ B それぞれに時計ウィジェットを表示している, **When** モニタ A の時計をモニタ B 内の時計とは異なる位置に移動する, **Then** 各モニタの表示位置はそれぞれ独立して保持される
3. **Given** モニタごとの表示設定を行った後, **When** アプリを再起動する, **Then** モニタごとの表示/非表示と位置がすべて復元される
4. **Given** 型番の異なるモニタ A とモニタ B それぞれでウィジェットの位置を変えた後 (どちらの型番も、保存済みの設定は 1 つだけ), **When** アプリを終了し、モニタ A のケーブルを別の端子につなぎ直してアプリを起動する, **Then** モニタ A のウィジェットは、つなぎ直す前と同じ表示/非表示・位置で表示される
5. **Given** 同じ型番のモニタ C とモニタ D を 2 つの端子につなぎ、それぞれでウィジェットの位置を変えた後, **When** アプリを再起動する, **Then** 端子ごとに、それぞれの表示/非表示と位置が復元される
6. **Given** 以前のバージョンでモニタごとの表示設定を保存していた, **When** このバージョンにアップデートしてアプリを起動する, **Then** つながっている各モニタのウィジェットは、アップデート前と同じ表示/非表示・位置で表示される。以前に保存されていて、このときつながっていないモニタ (会議室のプロジェクターなど) は非表示になり、後でつないでも時計は表示されない (位置は保存されたままで、表示に戻すとその位置に出る)
7. **Given** 同じ型番のモニタ C とモニタ D を 2 つの端子につなぎ、それぞれでウィジェットの位置を変えた後, **When** アプリを終了し、2 台とも別の端子につなぎ直してアプリを起動する, **Then** 2 台とも初期値ではなく、C と D の設定が 1 つずつ使われる (どちらにどちらの設定が使われるかは保証しない)
8. **Given** 2 台以上のモニタが接続されている, **When** 詳細設定画面でモニタ A を選び、フォントサイズ・文字色・日付の表示などを変更する, **Then** モニタ A のウィジェットだけが変更内容を即座に反映し、モニタ B のウィジェットの見た目は変わらない
9. **Given** モニタ A とモニタ B で異なる見た目を設定した後, **When** アプリを再起動する, **Then** 各モニタのウィジェットは、それぞれの見た目で表示される
10. **Given** 以前のバージョンで見た目・位置ロック・最前面表示を設定していた, **When** このバージョンにアップデートしてアプリを起動する, **Then** 表示されている各モニタのウィジェットが、アップデート前と同じ見た目・位置ロック・最前面表示で表示される (US4-6 で非表示になったモニタも、表示に戻すと同じ見た目・位置ロック・最前面表示で表示される)
11. **Given** 詳細設定画面を開いている, **When** 画面を開いたままモニタをつなぐ、または取り外す, **Then** 詳細設定画面の「編集するモニター」の選択肢は、画面を開き直さなくても接続中のモニタに合わせて更新される
12. **Given** モニタ A とモニタ B それぞれにウィジェットを表示している, **When** モニタ A のウィジェットの右クリックメニューで位置ロック・最前面表示を切り替える, **Then** モニタ A のウィジェットだけが切り替わり、モニタ B のウィジェットの位置ロック・最前面表示は変わらない
13. **Given** 2 台以上のモニタにウィジェットを表示している, **When** モニタ B のウィジェットの右クリックメニューから「詳細設定」を開く, **Then** 詳細設定画面は、モニタ B を編集する状態で開く。詳細設定画面をすでに開いていた場合も、編集の対象がモニタ B に切り替わる
14. **Given** ほかのモニタの設定は保存済みで、保存済みの設定がないモニタ (会議室のプロジェクターなど) がある, **When** そのモニタをつなぐ (アプリの起動中でも、つないだ後にアプリを起動しても), **Then** そのモニタには時計ウィジェットが表示されない。詳細設定画面でそのモニタを選ぶと、「このモニターに表示する」はオフで、見た目は既定値になっている
15. **Given** 設定ファイルがない (初めて起動する), **When** アプリを起動する, **Then** プライマリモニタに、既定の見た目で時計ウィジェットが表示される。ほかのモニタには表示されない
16. **Given** モニタ A を表示、モニタ B を非表示にしている, **When** 詳細設定画面の「編集するモニター」を開く, **Then** モニタ B の選択肢には、非表示であることが分かる表記が付いている。モニタ A を編集している間にモニタ A を取り外すと、編集の対象はプライマリモニタに切り替わる
17. **Given** モニタ A のウィジェットだけ位置ロックを有効にしている, **When** モニタ A とモニタ B のウィジェットをそれぞれドラッグする, **Then** モニタ A のウィジェットは動かず、モニタ B のウィジェットは動く
18. **Given** モニタ A は位置ロック有効・最前面表示無効、モニタ B は位置ロック無効・最前面表示有効にしている, **When** アプリを再起動する, **Then** それぞれのモニタの位置ロック・最前面表示が、再起動前と同じに復元される

### Edge Cases

- モニタを取り外した(接続構成が変わった)状態でアプリを起動した場合、取り外されたモニタに割り当てられていた表示設定はどう扱われるか(接続時のために保持し、実際の表示には影響させない)
- アプリ稼働中にモニタが物理的に取り外された場合、そのモニタに表示していたウィジェットは自動的に非表示になる(表示/非表示・位置の設定自体は変更せず保持し、再接続時に同じ設定で表示を再開する)
- 設定ファイルが存在しない、または壊れている(不正な JSON)場合、アプリはデフォルト設定で正常に起動する
- 背景透過度を 100%(完全透明)にした場合でも、ウィジェットはドラッグ操作・右クリックメニュー操作が可能な状態を保つ
- 同じユーザーが誤って複数回アプリを起動しようとした場合、二重起動はせず既存のウィジェットにフォーカスする、または何もしない
- 全画面表示の他アプリ(動画・ゲーム等)がある場合でも、最前面表示 ON のウィジェットが常時表示され続けることをユーザーは期待する
- アンカー指定で配置されたウィジェットは、DPI スケールの変更・フォントサイズの変更・日付/曜日表示の ON/OFF など、ウィジェット自体の表示サイズが変わる要因があっても、指定したアンカー位置(隅寄せ等)の見た目を保ち続ける
- ドラッグで作業領域の端に達した後もマウスを動かし続けた場合、ウィジェットは端で止まる。拡大率の異なるモニタとの境界へ向かってドラッグしても、アプリが終了したり、ウィジェットが揺れたり、マウスを離した後に元の位置へ戻ったりしない
- アンカー指定で隅に寄せたウィジェットを外側へドラッグして端で止まった場合、見た目の位置は変わらないが、アンカー指定は解除され自由配置に切り替わる (FR-036)
- 自由配置のウィジェットが縁からちょうど余白と同じ距離にある場合も、その余白は選べる (選んでも位置は変わらない)。ドラッグで端に止めた直後 (縁までの距離が 0) は、狭め・広めのどちらも選べる
- 自由配置の間に余白を選んで縁から離した後、フォントサイズの変更などでウィジェットの表示サイズが変わっても、縁との間隔は保たれない (自由配置のため。間隔を保つにはアンカー指定を使う)
- 自由配置の間に選んだ余白は、次にアンカー指定したときの余白として使われる
- 同じ型番のモニタを 2 台、左右で入れ替えてつなぎ直した場合、設定はモニタの個体ではなく端子について
  いく (FR-040)。同じ型番の別の個体に買い替えた場合も、前のモニタの設定を引き継ぐ
- 1 台だけだった型番のモニタに、同じ型番のモニタをもう 1 台つないだ場合、前と同じ端子につながって
  いる方が前の設定を引き継ぎ、もう 1 台は新しいモニタとして扱う (非表示で始まる。FR-041)
- 同じ型番のモニタ 2 台のうち 1 台を外した場合、残った 1 台は、前と同じ端子の設定を使う。外した方の
  設定も、再びつないだときのために残す
  - 残った 1 台を前とは別の端子につなぎ直した場合は、その端子の設定が保存済みならそれを使う。なければ、
    使われていない 2 つの設定のうち、端子の番号順で先の方を使う (FR-040)
- 同じ型番のモニタ 2 台を、レイアウトの変更や引越しなどで別の端子につなぎ直した場合は、その型番の
  使われていない設定を、端子の番号順に 1 つずつ割り当てる (FR-040)。左右の設定が入れ替わることがあり、
  その場合は利用者が設定し直す
- 以前のバージョンで端子を挿し替えたことがあると、そのとき足された初期値の設定が残っており、別の端子に
  つなぎ直したときに、本来の設定ではなくそちらが割り当てられることがある。その場合も利用者が設定し直す
- モニタごとの見た目・位置ロック・最前面表示の設定も、表示/非表示・位置と同じく FR-040 の見分け方に
  従う。取り外したモニタのこれらの設定は、再びつないだときのために残す
- 非表示のモニタにはウィジェットがないため、その位置ロック・最前面表示は右クリックメニューで変えられ
  ない。表示に戻したときは、保存してある値で始まる
- 詳細設定画面で非表示に設定しているモニタも、見た目を編集するモニタとして選べる。表示に切り替えた
  ときに、その見た目で表示される
- 詳細設定画面で見た目を編集しているモニタが、画面を開いている間に取り外された場合、編集の対象は
  プライマリモニタに切り替わる (FR-042)
- 日付の区切り文字を設定ファイルで直接書き換える場合 (FR-026) も、モニタごとに指定する
- 保存済みの設定があるモニタがどれもつながっておらず、新しいモニタだけがつながっている場合 (ノート PC を
  閉じて、初めての場所の外部モニタにつないだ場合など)、どのモニタにも時計は表示されない。タスクトレイの
  常駐アイコンは表示されるので、そこから詳細設定画面を開いて表示に切り替える
- 詳細設定画面の「このモニターに表示する」をオフにして、すべてのモニタを非表示にすることもできる。
  その場合もタスクトレイから詳細設定画面を開いて戻せる

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは Windows へのログイン後、ユーザー操作なしに時計ウィジェットを自動的に起動し表示しなければならない(自動起動 ON 設定時)
- **FR-002**: システムは現在時刻を常時表示し、1 秒以内の周期で定期的に表示を更新しなければならない(実時刻との誤差が視認できるレベルにならないようにするため)
- **FR-003**: システムは日付表示の ON/OFF を設定できなければならない
- **FR-004**: システムは曜日表示の ON/OFF を設定できなければならない
- **FR-005**: ユーザーはフォントの種類を、システムにインストールされているフォントの中から選択できなければならない
- **FR-006**: ユーザーはフォントサイズを選択・調整できなければならない
- **FR-007**: ユーザーは文字色を選択できなければならない
- **FR-008**: ユーザーは背景の透過度を 0%(完全に不透明)から 100%(完全に透明)の範囲で調整できなければならない
- **FR-009**: ユーザーはウィジェットをマウスドラッグで、そのウィジェットが表示されているモニタの作業領域 (タスクバーを除いた領域) 内の自由な位置に移動できなければならない。ドラッグでウィジェットを作業領域の外や別のモニタへ動かすことはできず、作業領域の端に達したらウィジェットはそこで止まる
- **FR-010**: ユーザーは位置を「ロック」し、ロック中はドラッグによる移動を無効化できなければならない。ロック中はウィジェット本体の右クリックメニューからのアンカー指定 (FR-034) による移動も無効化し、アンカーの項目は表示したままグレーアウト(選択不可)にする。位置ロックはモニタごとに設定し、ロックしたモニタのウィジェットにだけ効く (FR-041)
- **FR-011**: ユーザーはウィジェットを常に最前面に表示するかどうかを ON/OFF 切り替えできなければならない (位置ロック (FR-010) と同じく、モニタごとに設定する。FR-041)
- **FR-012**: ユーザーは右クリックメニューから、最前面表示・位置ロック・アンカー指定(FR-034)をその場で切り替えられなければならない (Input で言う「クイック切替」に相当する機能である。モニタごとの表示/非表示は詳細設定画面からのみ切り替える。ウィジェット自身を右クリックメニューから非表示にすると再表示の手段がなくなり誤操作防止(Core Principle IV)に反するため、右クリックメニューでの表示/非表示切替は本バージョンの範囲外とする)。ウィジェット本体の右クリックメニューで切り替わるのは、そのウィジェットが表示されているモニタの設定だけとする (FR-041)。最前面表示・位置ロック・アンカー指定は、タスクトレイの常駐アイコンの右クリックメニューには置かない (FR-038)
- **FR-013**: ユーザーは別ウィンドウの詳細設定画面から、フォント・サイズ・色・背景色・背景透過度・秒/日付/曜日表示の ON/OFF・日付の区切り文字・曜日の表示形式・時刻と日付/曜日の改行有無・モニタごとの表示/非表示をすべて変更できなければならない。これらはすべて、選んだモニタについて変更する (FR-041・FR-042)。自動起動の ON/OFF は、詳細設定画面ではなくタスクトレイの右クリックメニューで切り替える (FR-038)
- **FR-014**: システムは接続されている各モニタについて、個別に表示/非表示を設定できなければならない(非表示に設定したモニタでは、最前面表示 (FR-011) の設定に関わらずウィジェットは表示されない)。表示/非表示は、詳細設定画面で選んだモニタの「このモニターに表示する」チェックで切り替える (FR-042)
- **FR-015**: システムは表示対象の各モニタについて、そのモニタ内での表示位置を個別に保持しなければならない
- **FR-016**: システムはすべての設定(表示内容、見た目、配置、モニタ別設定、自動起動設定)を JSON ファイルとして保存し、Windows レジストリを使用してはならない
- **FR-017**: システムは次回起動時に、保存済みの設定をすべて復元して同じ状態で表示を再開しなければならない
- **FR-018**: システムは設定ファイルが存在しない場合、または内容が不正で読み込めない場合、デフォルト設定を用いて正常に起動しなければならない。内容が不正で読み込めなかった場合は、デフォルト設定にフォールバックしたことをユーザーに通知しなければならない(通知の具体的な UI 表現は実装時に妥当な形で決めてよい)
- **FR-019**: ユーザーは自動起動の ON/OFF を設定できなければならない
- **FR-020**: システムは、モニタごとに異なる DPI スケーリングが設定されている環境や高 DPI 環境において、DPI 設定・スケーリングの違いによらずフォントサイズやウィンドウ位置が崩れないように表示しなければならない
- **FR-021**: 詳細設定画面での変更はすべて即時反映・自動保存としなければならない。変更前の状態に戻す明示的な「キャンセル」操作は提供しない
- **FR-022**: システムは設定ファイルへの書き込みに失敗した場合(保存先への書き込み権限がない場合を含む)でもクラッシュせず動作を継続しなければならない。ただしその場合、失敗した変更内容はそのセッション中は永続化されない
- **FR-023**: ユーザーは右クリックメニューからアプリケーションを完全に終了できなければならない(具体的な文言・配置は実装時に妥当な形で決めてよい)
- **FR-024**: システムは秒表示の ON/OFF を設定できなければならない(OFF の場合も、実際の表示更新自体は FR-002 の通り 1 秒以内の周期で継続する)
- **FR-025**: ユーザーは時刻表示と日付/曜日表示それぞれについて、独立してフォントサイズ・文字色を設定できなければならない(フォント種類は FR-005 の通り、1 つのウィジェットの時刻表示と日付/曜日表示で共有する)
- **FR-026**: ユーザーは日付の区切り文字を、詳細設定画面で「/」「-」「.」から選択できなければならない。設定ファイルを直接書き換えた場合は、任意の文字列 (空欄を含む。長さの上限は設けない) を区切り文字として使えなければならない。設定ファイルに区切り文字の項目がない、または値が指定されていない (`null`) 場合は「/」を使い、詳細設定画面でも「/」を選んだ状態で表示する。詳細設定画面は、設定ファイルの区切り文字が選択肢にない場合、どの選択肢も選ばれていない状態で表示しなければならない。画面で区切り文字の選択肢を選び直さない限り、区切り文字を変えてはならない (画面を開いただけの場合や、ほかの項目だけを変えた場合も含む。選び直した場合は、その選択肢に置き換わる)
- **FR-027**: ユーザーは曜日の表示形式を「(月)」「月曜日」「Mon.」「Monday」の中から選択できなければならない
- **FR-028**: システムは日付表示・曜日表示がともに ON の場合、両者を改行せず常に同一行に表示しなければならない
- **FR-029**: ユーザーは日付/曜日表示を、時刻表示に対して上・下・左・右のいずれの位置に表示するかを設定できなければならない
- **FR-030**: ユーザーは背景色を選択できなければならない(背景透過度 (FR-008) とは独立して設定する)
- **FR-031**: システムはタスクトレイに常駐アイコンを表示し、それをクリックすることで(「最前面表示」(FR-011) の設定に関わらず)すべての時計ウィジェットを最前面に呼び戻せなければならない
- **FR-032**: ユーザーはタスクトレイの常駐アイコンを右クリックして表示されるメニューからも、アプリケーションを完全に終了できなければならない(FR-023 と同等の手段をタスクトレイからも提供する)
- **FR-033**: アプリケーションの実行ファイル・ウィンドウ・タスクトレイアイコンは、既定のアイコンではなく時計をイメージした専用のアイコン画像を使用しなければならない(具体的なデザインは実装時に決めてよい)
- **FR-034**: システムはウィジェットの表示位置を、ピクセル単位の絶対座標(FR-009 のドラッグによる自由配置)に加えて、モニタ内での横位置(左/中央/右)と縦位置(上/中央/下)の組み合わせによるアンカー指定でも設定できなければならない。アンカー指定はモニタごとに独立して保持される(既存のモニタ内での表示位置(FR-015)と同じ粒度)。アップデート前から保存済みの絶対座標は「自由配置」として扱い、アンカー指定はユーザーが右クリックメニューから新たに選んだ場合のみ有効になる(既存ユーザーの表示位置はアップデートだけでは変化しない)
- **FR-035**: ユーザーはアンカー指定を使う場合、画面端からの余白を「狭め」「広め」の 2 段階から選択できなければならない。この余白はピクセル単位の固定値ではなく、DPI スケールが変わっても見た目の余白感が概ね一定に保たれる相対的な段階として扱わなければならない。右クリックメニューでは、アンカー指定中は選択中の余白にチェックを表示し、自由配置中は余白のどの項目にもチェックを表示しない (横位置・縦位置と同じ扱い)。余白の値は自由配置中も保持し、次にアンカー指定したときに使う
- **FR-036**: システムは、アンカー指定で配置されたウィジェットをユーザーがドラッグ操作した場合、そのモニタの表示位置を(FR-009 と同様に)自由な座標として扱わなければならない。以後はそのモニタについてアンカー指定ではなくドラッグ後の座標を使用する。作業領域の端で止まって位置が変わらなかった場合や、クリックしただけの場合も、ドラッグ操作をしたものとして同じように扱う
- **FR-037**: ユーザーは、ウィジェット本体の右クリックメニューから、そのウィジェットが表示されているモニタのアンカー指定(横位置・縦位置・余白)を、詳細設定画面を開くことなく直接切り替えられなければならない。本体の右クリックメニューにはモニタを選ぶ階層を設けず、自分のモニタの設定のみを直接表示する
- **FR-038**: ユーザーは、タスクトレイの常駐アイコンの右クリックメニューから、詳細設定画面を開く・自動起動 (FR-019) の ON/OFF を切り替える・アプリケーションを終了する (FR-032)、の 3 つの操作を行えなければならない。自動起動の項目は、現在の ON/OFF をチェック表示する。位置ロック・最前面表示・アンカー指定はモニタごとの設定のため (FR-041)、タスクトレイのメニューには置かず、ウィジェット本体の右クリックメニュー (FR-012・FR-037) で切り替える
- **FR-039**: ユーザーは、自由配置のウィジェットについてもウィジェット本体の右クリックメニューから余白を選び、作業領域の縁から離せなければならない。システムは、ウィジェットから作業領域の上下左右の縁までの距離を調べ、距離が選んだ余白以下の縁 (2 つあれば両方) から、選んだ余白ぶん内側へウィジェットを移動する。移動後も自由配置のままとし、アンカー指定には切り替えない。どの縁までの距離もその余白より大きい場合、その余白の項目はグレーアウト (選択不可) にする。距離と余白の比較は、DPI スケールを考慮した実際の画面上の大きさで行う (FR-035)
- **FR-040**: システムは、モニタごとの設定 (FR-014・FR-015・FR-034・FR-041) を保存・復元するとき、モニタをそのメーカーと型番で見分けなければならない。同じ型番のモニタが同時に複数つながっている間は、つないでいる端子でも見分け、端子ごとに設定を保持する。型番の異なるモニタは、別の端子につなぎ直しても同じモニタとして扱い、前の設定を引き継ぐ。つないだ端子の設定が保存されていないモニタには、同じ型番の設定のうち、接続中のどのモニタにも使われていないものを、端子の番号順に割り当てる (同じ型番のモニタが複数ある場合や、同じ型番の設定が複数保存されている場合に、どれが前の設定かは保証しない。Edge Cases)。以前のバージョンで保存されたモニタごとの設定は、この見分け方に引き継ぎ、アップデートしただけで表示位置が変わらないようにしなければならない。表示/非表示は、アップデートしたときにつながっているモニタについてだけ変えない (つながっていないモニタは非表示にする。FR-041)
- **FR-041**: システムは表示設定とウィンドウ挙動設定 (Key Entities。見た目のすべての項目と、位置ロック・最前面表示) をモニタごとに独立して保持し、各モニタのウィジェットにそのモニタの設定を適用しなければならない。アプリ全体で共通とするのは、自動起動 (FR-019) だけとする。以前のバージョンで保存されたアプリ全体で共通の表示設定・ウィンドウ挙動設定は、保存済みのすべてのモニタに引き継ぎ、アップデートしただけで見た目や動きが変わらないようにしなければならない。以前のバージョンで保存されたモニタのうち、アップデートして初めて起動したときにつながっていないモニタは、非表示にしなければならない (以前のバージョンは、一度つないだモニタをすべて表示する設定で保存していたため。つながっているモニタの表示/非表示は変えない)。設定がまだ保存されていないモニタ (新しくつないだモニタ。FR-040 で割り当てる保存済みの設定がないモニタを指す。割り当てる設定があるモニタは、その設定の表示/非表示・見た目などをそのまま使う) は、表示設定・ウィンドウ挙動設定を既定値 (初めて起動したときと同じ値) とし、時計ウィジェットを表示しない状態 (FR-014) で始めなければならない。ただし、保存済みのモニタの設定が 1 つもない場合 (初めて起動したとき、FR-018 で既定値に戻ったとき) は、プライマリモニタだけを表示する状態で始めなければならない (これまでの、新しいモニタにも、初めて起動したときや FR-018 で既定値に戻ったときのすべてのモニタにも表示する動きから変わる)。この判定はアプリの起動時だけ行い、設定ファイルにモニタの設定が 1 つもない場合も、初めて起動したときと同じに扱う
- **FR-042**: ユーザーは詳細設定画面の上部にある「編集するモニター」のドロップダウンで、設定を変更するモニタを選べなければならない。画面のその他の項目は、選んだモニタの設定を表示・変更する。選べるのは接続中のモニタ (非表示に設定したモニタを含む) とし、各選択肢には、そのモニタが非表示であることが分かる表記を付ける。詳細設定画面を開いたときは、ウィジェット本体の右クリックメニューから開いた場合はそのウィジェットのモニタを、タスクトレイの右クリックメニューから開いた場合はプライマリモニタを選んだ状態にしなければならない。詳細設定画面を開いたまま、別のモニタのウィジェットの右クリックメニューから開き直した場合は、そのモニタに切り替える。タスクトレイの右クリックメニューから開き直した場合は、今の選択を保つ。詳細設定画面を開いている間にモニタの接続・取り外しがあった場合、システムはドロップダウンの選択肢を、画面を開き直さなくても接続中のモニタに合わせて更新しなければならない。編集中のモニタがつながっている限り、選択は変えない (モニターの番号が振り直された場合も、同じモニタを選んだままにする)。編集中のモニタが取り外された場合は、プライマリモニタの編集に切り替える

### Key Entities

- **表示設定 (Appearance Settings)**: フォント種類 (1 つのウィジェットの時刻表示と日付/曜日表示で共有)、時刻表示・日付/曜日表示それぞれのフォントサイズ・文字色、背景色・背景透過度、秒表示/日付表示/曜日表示の ON/OFF、日付の区切り文字、曜日の表示形式、時刻に対する日付/曜日表示の位置(上/下/左/右)。見た目に関する設定で、モニタごとに 1 つずつ保持される (FR-041)
- **ウィンドウ挙動設定 (Window Behavior Settings)**: 最前面表示 ON/OFF、位置ロック ON/OFF。モニタごとに 1 つずつ保持される (FR-041)
- **モニタ別配置 (Monitor Placement)**: モニタを識別する情報 (メーカーと型番。同じ型番のモニタが複数つながっている場合は、つないでいる端子も。FR-040)、そのモニタでの表示/非表示、そのモニタ内でのウィンドウ位置、そのモニタの表示設定とウィンドウ挙動設定 (FR-041)。位置は「絶対座標(ドラッグによる自由配置)」または「アンカー指定(横位置・縦位置・余白段階)」のいずれかとして保持される。アップデート前から保存済みの絶対座標は自由配置として扱われ、アンカー指定はユーザーが右クリックメニューから選んだ場合のみ有効になる。余白段階は自由配置の間も保持され、次にアンカー指定したときに使われる。モニタごとに複数保持される
- **アプリケーション設定 (Application Settings)**: 自動起動 ON/OFF、設定ファイルの保存場所

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: デスクトップが操作可能になった時点(OS 側のログイン処理時間は含まない)から、デスクトップに時計が表示されるまでの時間が 5 秒以内である
- **SC-002**: 自動起動を有効にしたユーザーの 100%が(Windows 側の自動起動の仕組みが正常に機能する環境において)、ログイン後に自分で何かを操作しなくても時計の表示を確認できる (表示する設定のモニタが 1 台以上つながっている場合。新しいモニタだけがつながっている場合は Edge Cases)
- **SC-003**: ユーザーは詳細設定画面を開いてから、見た目(フォント・色・透過度)の変更を完了するまでを 1 分以内に行える
- **SC-004**: 位置ロックを有効にしている間、ドラッグ操作や右クリックメニューからのアンカー選択によってウィジェットの表示位置が変化する事象は発生しない
- **SC-005**: マルチモニタ環境において(接続されているモニタの台数や配置の組み合わせによらず)、モニタごとの表示/非表示・表示位置・見た目・位置ロック・最前面表示の設定は、アプリの再起動や PC の再起動を経ても 100%正しく復元される。以前のバージョンからアップデートした場合も同様に 100%正しく復元される (ただし、アップデートしたときにつながっていないモニタは非表示になる。FR-041)。型番の異なるモニタを別の端子につなぎ直した場合も、保存済みの設定にその型番のものが 1 つだけであれば同様に 100%正しく復元される (FR-040。その型番の設定が 2 つ以上保存されている場合は対象外。Edge Cases)
- **SC-006**: 詳細設定画面を閉じている間(時計表示の更新のみが発生しているアイドル状態)、CPU 使用率が 1%未満、メモリ使用量が 100MB 未満に収まる(詳細設定画面を開いている間は対象外)
- **SC-007**: アンカー指定で配置されたウィジェットは、DPI スケールの変更やフォントサイズ変更などでウィジェットの表示サイズが変わる事象が発生しても、指定した位置関係(画面の隅寄せなど)が崩れる事象は発生しない
- **SC-008**: 位置ロックが無効な状態で、ウィジェットを表示中のモニタの作業領域の外 (隣のモニタやタスクバーの方向) へドラッグしても、ウィジェットが作業領域からはみ出す・揺れる・マウスを離した後に元の位置へ戻る・アプリが終了する、といった事象は発生しない
- **SC-009**: 詳細設定画面であるモニタの見た目を変更したとき、または右クリックメニューであるモニタの位置ロック・最前面表示を切り替えたとき、ほかのモニタのウィジェットの見た目・位置ロック・最前面表示が変わる事象は発生しない
- **SC-010**: 詳細設定画面を開いたままモニタをつないだり取り外したりしても、画面を開き直すことなく、モニタの一覧が接続中のモニタと食い違わない状態になる

## Assumptions

- 表示言語・日付/曜日の表記は日本語環境(ユーザーのロケール)を前提とする
- フォントは、ユーザーの PC にインストール済みのフォントの中から選択できれば十分であり、フォントファイルの追加インストール機能は範囲外とする
- Windows 標準でフォントが存在する前提とし、インストール済みフォントが極端に少ない(ほぼ存在しない)特殊な環境への特別な対応は行わない
- 「透過度 100%」であってもウィジェットの操作(ドラッグ、右クリックメニュー)はできる状態を維持し、完全にクリックが透過してデスクトップの背後にあるアイコン等を直接操作できるようにする「クリックスルー」機能は本バージョンの範囲外とする
- アプリの二重起動防止(同時に複数プロセスを起動させない)は基本的な品質として必要だが、詳細な排他制御の方式は実装時に妥当な標準的手法を選定してよい
- ウィジェットを完全に終了させる操作(アプリ終了)は右クリックメニューに含まれる想定とし、詳細な文言・配置は実装時に妥当な形で決めてよい
- モニタが取り外され再接続された場合、以前の設定 (表示/非表示・位置・見た目・位置ロック・最前面表示) を維持する。どのモニタを同じモニタとみなすかは FR-040 に従う
- メーカーと型番をモニタ側から読み取れないモニタ (汎用ドライバで認識されるモニタなど) は、同じ型番のモニタとしてまとめて扱い、特別な見分け方は設けない (Core Principle I)
- このバージョンで使った後に以前のバージョンへ戻した場合、モニタごとの設定が保たれることは保証しない (初期値に戻ってもよい。以前のバージョンへ戻す操作への対応は範囲外とする)
- 対象ユーザーは 1 台の PC を 1 人で使う個人利用が前提であり、マルチユーザーでの設定共有・同期は範囲外とする
- 同一 PC に複数の Windows ユーザーアカウントが存在する場合でも、設定ファイルはユーザーごとの `%APPDATA%` 配下に保存されるため、アカウントごとに設定が独立することを特別な設計なしに満たせる想定とする
- アンカー指定の横位置×縦位置は 9 通りの組み合わせをすべて許可し、「中央×中央」のように実用性が低そうな組み合わせも特別扱いで除外しない(過剰な作り込みを避ける、Core Principle I)
- アンカー指定の余白は「狭め」「広め」の 2 段階のみとし、3 段階以上への細分化は行わない(過剰な設定項目の増加を避ける、Core Principle I)
- アップデート前から保存済みの絶対座標を持つモニタ別配置は「自由配置」モードとして扱い、初期状態ではアンカー指定を持たない。新規に接続されたモニタなど、まだ表示位置が一度も保存されていないケースの初期値は実装時の妥当な既定値(例: 既存の初期配置ロジックを踏襲)でよい (新しいモニタは非表示で始まるため (FR-041)、この位置は、表示に切り替えたときに使われる)
- ドラッグで作業領域の端に止まっている間は、マウスをつかんだ位置とウィジェットの位置関係がずれてよい。マウスを内側へ戻したときに、どの時点でウィジェットが再び動き出すかの細かい挙動は実装時に妥当な形で決めてよい
- ドラッグ中にモニタの構成 (接続・取り外し・拡大率) が変わる場合の特別な扱いは設けない。変化後は既存の FR-020 と Edge Cases の扱いに従う
- 設定ファイルで任意の区切り文字を使えることは、利用者向けの説明 (README 等) には書かない隠し機能とする。設定ファイルは、アプリを終了してから書き換える前提とする (起動中に書き換えた場合の扱いは、他の設定項目と同じく定めない)
- 設定ファイルで区切り文字に絵文字を指定した場合、絵文字はカラーではなく、日付の文字色の単色で表示される。カラーで表示するための特別な対応は行わない (Core Principle I)
- 区切り文字に改行などの制御文字や、極端に長い文字列を指定した場合の見た目は定めない。普段の操作では起きないため (constitution の品質の線引き)
- FR-039 で「範囲内の縁が 2 つ」と言うときは、隅の近くで縦と横の縁が 1 つずつ範囲内になる場合を想定している。ウィジェットが作業領域とほぼ同じ大きさで、向かい合う縁 (左と右、または上と下) の両方が範囲内になる場合の動きは、本バージョンでは定めない (ウィジェットの大きさの上限とあわせて issue #45 で検討する)
- 詳細設定画面を開いている間に、Windows の設定でプライマリモニタが変わった場合の扱いは定めない。普段の操作ではまず起きないため (constitution の品質の線引き)
- 選んだモニタの見た目を、全モニタに一度に適用する手段は設けない。見た目は、モニタごとに設定してもらう (Core Principle I)
- 新しくつないだモニタと、以前のバージョンからアップデートしたときにつないでいなかったモニタには時計が表示されないため、表示するには詳細設定画面を開いてそのモニタを選ぶよう、利用者向けの説明 (公開リポジトリの README) に書く。アプリ内のヘルプは設けない
- このバージョンで使った後に以前のバージョンへ戻した場合、モニタごとの見た目・位置ロック・最前面表示の設定が保たれることは保証しない (モニタごとの設定と同じく、以前のバージョンへ戻す操作への対応は範囲外とする)
