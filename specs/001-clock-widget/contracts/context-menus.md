# Contract: 右クリックメニュー (ウィジェット本体・タスクトレイ)

**Feature**: `001-clock-widget` | **Date**: 2026-09-24 (2026-09-26 更新: 自由配置のときの余白、issue #43。2026-10-01 更新: モニタごとの設定とタスクトレイのメニューの簡素化、issue #53)

ウィジェット本体とタスクトレイの右クリックメニューの項目構成を定義する (FR-010, FR-012,
FR-019, FR-023, FR-031, FR-032, FR-035, FR-037, FR-038, FR-039)。実装時と `quickstart.md` の手動確認時に、
この契約と照合して確認する。設計判断の経緯は [`research.md`](../research.md) #17・#24 を参照。

2026-10-01 に、位置ロック・最前面表示をモニタごとの設定にし (FR-041)、タスクトレイのメニューを
「詳細設定...」「自動起動」「終了」だけにした (FR-038 の改訂)。それまでの、本体とトレイを同じ構成に
揃える形は取り下げた。

メニュー名の「配置」は、spec.md の「アンカー指定」(FR-034) のこと。コード上は
`MonitorPlacement.Anchor` / `AnchorMargin` にあたる。

## ウィジェット本体の右クリックメニュー

```text
詳細設定...        (このウィジェットのモニタを選んだ状態で開く。FR-042)
─────────
位置ロック          ✓ (このモニタの WindowBehavior.PositionLocked)
最前面表示          ✓ (このモニタの WindowBehavior.TopMost)
配置              ▶ [配置サブメニュー] (このウィジェットが乗っているモニタが対象)
─────────
終了
```

- 位置ロック・最前面表示は、このウィジェットのモニタだけを切り替える。ほかのモニタのウィジェットは変わらない
  (FR-012、2026-10-01 改訂)

## タスクトレイの右クリックメニュー

```text
詳細設定...        (プライマリモニタを選んだ状態で開く。開いていれば、選択を変えずに前に出す。FR-042)
─────────
自動起動            ✓ (AutoStartEnabled)
─────────
終了
```

- 2026-10-01 に、位置ロック・最前面表示・配置 (とモニタを選ぶ階層) をなくし、自動起動を詳細設定画面から移した
  (FR-038 の改訂、research.md #24)
- 「自動起動」を選ぶと ON/OFF を反転する。切り替えに失敗したら値を戻し、メッセージを出す (issue #18)
- スタートアップフォルダのショートカットを書き換えるのは、「自動起動」を選んだときだけ (issue #20)
- トレイアイコンの左クリック (すべてのウィジェットを最前面へ呼び戻す、FR-031) は変更しない

## 配置サブメニュー (本体のメニューのみ。2026-10-01 まではトレイと共通)

```text
横位置 ▶ 左 / 中央 / 右
縦位置 ▶ 上 / 中央 / 下
余白   ▶ 狭め / 広め
```

(2026-09-24 変更: 当初は 9 つの配置を 1 列に並べていたが、実機で「縦にずらずら並んで直感的に
分かりにくい」との指摘があり、横位置・縦位置を別々に選ぶ形にした。research.md #15)

- 横位置は `Anchor` の横の成分、縦位置は縦の成分にチェックを付ける。自由配置中
  (`Anchor` = null) は横位置・縦位置のどれにもチェックを付けない
- 余白は、アンカー指定中は現在の `AnchorMargin` 側にチェックを付ける。自由配置中はどちらにも
  チェックを付けない (横位置・縦位置と同じ扱い。2026-09-26 変更、以前は常にチェックを付けていた)
- 余白の大きさは、狭め = 8 DIP、広め = 24 DIP (拡大率 100% で 8 px / 24 px、150% で 12 px /
  36 px)。値は実機で調整してよい (research.md #15)
- 横位置 (または縦位置) を選ぶと、対象モニタの `Anchor` を更新してウィジェットを移動し、
  設定を保存する。もう片方の軸は以下のとおり決める
  - アンカー指定中: もう片方の軸は今の値のまま
  - 自由配置中: もう片方の軸は、今の位置から一番近いものにする。作業領域を 3 等分し、
    ウィジェットの中心がある所を選ぶ (例: 画面下の方にあるウィジェットで「横位置 → 右」を
    選ぶと右下へ動く)
- 余白を選ぶと `AnchorMargin` を更新して保存する。その後の動きは状態によって変わる
  - アンカー指定中: アンカー指定のまま、新しい余白で再配置する
  - 自由配置中: 作業領域の上下左右の縁のうち、ウィジェットまでの距離がその余白以下の縁から、
    余白ぶん内側へ動かす。隅の近くで縦と横の縁が両方とも範囲内なら、両方から離す。動かした後も
    自由配置のままで、チェックは付かない (FR-039、research.md #19)

## 自由配置中の余白のグレーアウト (FR-039)

- 自由配置中は、メニューを開いた時点のウィジェットの位置で、余白の項目ごとに選べるかを決める
  - どれかの縁までの距離がその余白以下なら選べる。ちょうど同じ距離でも選べる (選んでも動かない)
  - どの縁までの距離もその余白より大きければ、その項目をグレーアウトする
  - 例 (拡大率 100%): 右の縁から 16 px なら、狭め (8 px) はグレーアウト、広め (24 px) は選べる
- 「余白」の親項目は有効のままにし、サブメニューを開けるようにする (位置ロック中と同じ理由)
- アンカー指定中は、今までどおり両方とも選べる
- 2026-10-01 までは、トレイでも同じ判定を使っていた (トレイから配置をなくしたため、今は本体だけ)

## 位置ロック中の表示 (FR-010)

- 位置ロックが ON の間は、配置サブメニューの末端の選択肢 (左/中央/右、上/中央/下、狭め/広め) を
  グレーアウト (選択不可) にする
- 親の「配置」と途中の「横位置」「縦位置」「余白」は有効のままにし、
  サブメニューを開けるようにする。
  WPF では無効にした親のサブメニューは開けないため、親ごと無効にすると spec の
  「項目は表示されたままグレーアウト」(Acceptance Scenario 10) を満たせず、今どの配置が
  選ばれているかも確認できなくなる
- 項目自体は表示したままにし、非表示にはしない (spec.md の Clarifications)。チェック状態は
  ロック中も通常どおり表示する
- 位置ロック・最前面表示・詳細設定・終了はロック中も操作できる
- 位置ロックはモニタごとの設定なので、グレーアウトするかは、そのウィジェットのモニタの位置ロックで決める
  (2026-10-01 改訂)

## 状態の同期

- どちらのメニューも、開くたびに最新の設定値 (自由配置中の余白は、その時点のウィジェットの位置) から
  チェック状態とグレーアウトを決める
- 位置ロック・最前面表示はモニタごとの値なので、本体のメニューで変えると、そのウィジェットにだけ反映する
  (2026-10-01 改訂。それまではアプリ全体で 1 つの値で、全ウィジェットに反映していた)
