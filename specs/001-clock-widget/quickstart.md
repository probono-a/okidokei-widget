# Quickstart: 常駐デスクトップ時計ウィジェット

**Feature**: `001-clock-widget`

実装完了後、各ユーザーストーリーが動作することを手動で確認するための手順。自動テストで
検証できるのは `OkidokeiWidget.Core` のロジック(設定の読み書き・モニタ識別)のみであり、
実際の見た目・操作感は本手順で目視確認する。

## 前提条件

- Windows 11
- .NET 10 SDK (Windows Desktop ワークロード込み)
- リポジトリをクローン済みで、`src/OkidokeiWidget.App` が実装済みであること

## セットアップ

```powershell
dotnet build .\src\OkidokeiWidget.App\OkidokeiWidget.App.csproj
```

初回起動時、設定ファイルが存在しないことを確認したい場合は事前に削除する:

```powershell
Remove-Item "$env:APPDATA\OkidokeiWidget\settings.json" -ErrorAction SilentlyContinue
```

## 単体テストの実行

見た目に依存しないロジック([`data-model.md`](./data-model.md)、
[`contracts/settings-file.md`](./contracts/settings-file.md) 参照)の検証:

```powershell
dotnet test .\tests\OkidokeiWidget.Core.Tests\OkidokeiWidget.Core.Tests.csproj
```

期待結果: 全テストが成功する。特に「設定ファイルなし/不正な JSON でもデフォルト設定で
正常に読み込める」テスト (FR-018 対応) が含まれること。

アンカー指定の追加 (2026-09-24) に伴い、以下のテストも含まれること:

- `Anchor`・`AnchorMargin` を持たない既存の設定ファイルを読み込むと、自由配置・`Narrow` に
  なる (FR-034、contracts/settings-file.md の後方互換性)
- 9 つの配置それぞれについて、作業領域・ウィジェットサイズ・余白・DPI スケールから期待どおりの
  位置が計算される。ウィジェットが作業領域より大きい場合は作業領域内へ収まる (FR-035)
- 横位置だけ (縦位置だけ) を選んだとき、もう片方の軸が、アンカー指定中なら今の値のまま、
  自由配置中なら今の位置から一番近いものになる (research.md #15 の追記)

## シナリオ検証

### US1: デスクトップに時計を常時表示する (P1)

```powershell
dotnet run --project .\src\OkidokeiWidget.App\OkidokeiWidget.App.csproj
```

- **期待結果**: 数秒以内にデスクトップ上に時計ウィジェットが表示され、現在時刻が 1 秒単位で
  更新され続ける (SC-001, SC-002)
- 詳細設定で日付・曜日表示を ON にすると、時刻に加えて日付・曜日が表示される
- アプリが起動している状態でもう一度起動を試み、2 つ目のプロセスが新しいウィンドウを作らずに
  そのまま終了することを確認する(二重起動防止、research.md #6、Edge Case 参照)

### US2: 見た目のカスタマイズ (P2)

- ウィジェットを右クリック→詳細設定を開く
- フォント種類・サイズ・文字色を変更し、即座にウィジェットへ反映されることを確認する
- 背景透過度スライダーを動かし、リアルタイムに背景の透け具合が変わることを確認する
- 日付/曜日表示の位置(上/下/左/右)を切り替え、時刻表示に対する配置が変わることを確認する
- アプリを終了して再起動し、変更した見た目が保持されていることを確認する (SC-003)
- 日付の区切り文字 (FR-026、2026-09-28 追加、issue #60)
  - 詳細設定画面で区切り文字に「.」を選び、日付が `2026.09.28` の形になることを確認する
  - 2026-10-01 改訂 (issue #53): 以下で書き換える `DateSeparator` は、ルートのものではなく、`Monitors` の中の
    あるモニタの `Appearance.DateSeparator` である。詳細設定画面では、「編集するモニター」でそのモニタを選んで確かめる
    - ルートに `Appearance` を足してはいけない。以前のバージョンのファイルとして引き継ぎが走り、全モニタの見た目が
      上書きされ、つながっていないモニタは非表示になる (contracts/settings-file.md の読み込み契約)
  - アプリを終了し、`settings.json` の `DateSeparator` を `"🍣"` に書き換えてから起動する
    - 起動した時点で、`settings.json` の `DateSeparator` は `"\uD83C\uDF63"` の形に書き換わっていてよい (値は同じ。contracts/settings-file.md)
    - 日付が `2026🍣09🍣28` の形 (絵文字は日付の文字色の単色) で表示されることを確認する
    - 詳細設定画面を開くと、区切り文字の欄が空欄になっていることを確認する (US2 のシナリオ 6)
    - 文字色など、区切り文字以外の項目を 1 つ変えてから画面を閉じ、`settings.json` の `DateSeparator` が `"🍣"` と同じ文字 (`"\uD83C\uDF63"` の形で書き出されていてもよい) のままで、アプリを再起動しても日付が 🍣 で区切られることを確認する
    - もう一度開いて区切り文字に「/」をマウスで選ぶと、日付が `2026/09/28` に戻り、`settings.json` も `"/"` になることを確認する (research.md #21 の前提 3)
  - アプリを終了し、`DateSeparator` を `null` に書き換えてから起動する
    - 日付が `2026/09/28` の形で表示され、詳細設定画面の区切り文字の欄が「/」を選んだ状態になっていることを確認する
    - 区切り文字以外の項目を 1 つ変えてから画面を閉じ、`settings.json` の `DateSeparator` が `null` のままであることを確認する

### US3: 配置とロック (P2)

- ロック無効の状態でウィジェットをドラッグし、位置が移動することを確認する
- 右クリックメニューから「位置ロック」を有効にし、ドラッグしても位置が変化しないことを
  確認する (SC-004)
- 右クリックメニューから「最前面表示」を切り替え、他ウィンドウの手前/背後に切り替わることを
  確認する
- 「最前面表示」を OFF にした状態でウィジェットを他のウィンドウの背後に隠し、タスクトレイの
  常駐アイコンをクリックしてウィジェットが最前面に戻ることを確認する
- タスクトレイの常駐アイコンを右クリックし、「終了」でアプリが終了することを確認する
- タスクバー・タスクトレイ・ウィンドウのアイコンが既定のものではなく専用のアイコンに
  なっていることを確認する (FR-033)

#### アンカー指定 (FR-034〜FR-038、2026-09-24 追加)

メニューの項目構成は [`contracts/context-menus.md`](./contracts/context-menus.md) と照合する。

- 既存の `settings.json` (アップデート前のもの) のまま起動し、ウィジェットの位置が変わって
  いないことを確認する (FR-034)
- 自由配置のウィジェットを画面の下の方に置き、本体を右クリック→「配置」→「横位置」→「右」を
  選ぶ。ウィジェットが右下へ移動する (縦は今の位置から一番近い「下」になる) ことを確認する
- 続けて「縦位置」→「上」を選び、右上へ移動することを確認する。横位置・縦位置の組み合わせ
  9 通りで、作業領域 (タスクバーに重ならない範囲) の該当する位置へ移動することを確認する
- 「余白」→「広め」に切り替え、画面端からの隙間が広がることを確認する
- 右上に配置した状態で、詳細設定からフォントサイズを大きくする・日付表示を ON/OFF する。
  ウィジェットの右上が画面の右上から離れないことを確認する (SC-007)
- ディスプレイ設定の拡大率を変更し、右上の位置と余白の見た目が保たれることを確認する (SC-007)
- アンカー指定中にウィジェットをドラッグし、ドラッグ後の位置に留まること、再び右クリックすると
  「横位置」「縦位置」「余白」のどの項目にもチェックが付いていないことを確認する (FR-036、FR-035)
- 位置ロックを ON にし、本体のメニューで「配置」→「横位置」などのサブメニューは
  開けるが、末端の選択肢がグレーアウトして選べないことを確認する。今の配置のチェックはロック中も
  見えていること (FR-010、SC-004。2026-10-01 からトレイには配置がない)
- (2026-10-01 に取り下げ) タスクトレイのメニューが本体と同じ項目を持つこと、トレイから配置を変えることの確認。
  今のトレイのメニューの確認は、下の「モニタごとの設定 (2026-10-01 追加、issue #53・#17)」で行う

#### ドラッグで動かせる範囲 (FR-009・SC-008、2026-09-26 追加、issue #39)

- 位置ロックを OFF にし、ウィジェットを画面の上下左右の端、およびタスクバーの方へドラッグし続ける。
  作業領域の端で止まり、はみ出さない・タスクバーに重ならないことを確認する (FR-009)
- 端で止まったままマウスを端に沿って動かし、ウィジェットが端に沿って動くことを確認する。
  マウスを内側へ戻すと、再びマウスに追従して動くことを確認する
- (拡大率の異なる複数モニタ環境がある場合) 隣のモニタとの境界へ向かってドラッグし、境界の手前で
  止まること、揺れないこと、アプリが終了しないことを確認する。マウスを離した後、止まった位置に
  留まる (元の位置へ戻らない) ことを確認する (SC-008、issue #39 の再現手順)
- アプリを再起動し、端で止めた位置が復元されることを確認する (FR-015)
- 右下にアンカー指定したウィジェットを、さらに右下へドラッグして離す。位置は変わらないが、
  右クリックメニューの「横位置」「縦位置」のチェックが外れていることを確認する (FR-036)

#### 自由配置のときの余白 (FR-035・FR-039、2026-09-26 追加、issue #43)

- アンカー指定のウィジェットをドラッグして自由配置にし、「配置」→「余白」を開く。狭め・広めの
  どちらにもチェックが付いていないことを確認する (FR-035、Acceptance Scenario 16)
- 自由配置のウィジェットを右の縁にぴったり付け (縦は画面の中ほど)、「余白」→「狭め」を選ぶ。
  右の縁から少し内側へ動き、縦の位置は変わらないことを確認する。続けて「広め」を選び、さらに
  内側へ動くことを確認する。どちらの後も、横位置・縦位置・余白のチェックは付かないこと
  (FR-039、Acceptance Scenario 17)
- ウィジェットを右下の隅にぴったり付けて「広め」を選び、右と下の両方の縁から離れることを確認する
- ウィジェットを画面の中ほどに置き、「余白」の狭め・広めがどちらもグレーアウトしていることを確認する。
  縁から少しだけ (狭めより広く、広めより狭く) 離した所に置き、狭めだけがグレーアウトしていることを
  確認する (FR-039、Acceptance Scenario 18)
- (2026-10-01 に取り下げ) 本体とタスクトレイのメニューで、余白の状態が一致していることの確認。トレイには配置がなくなった
- 自由配置の間に「広め」を選んで縁から離した後、「横位置」→「右」を選ぶ。アンカー指定の余白も
  広めになっていること (余白のチェックが「広め」に付くこと) を確認する (spec.md の Edge Cases)
- アプリを再起動し、余白で離した位置が復元されることを確認する (FR-015)

### US4: マルチモニタでの独立管理 (P3、複数モニタ環境がある場合のみ)

- 詳細設定でモニタ B の表示を OFF にし、モニタ B の表示が消え、モニタ A に影響しないことを
  確認する
- モニタ A とモニタ B でそれぞれ異なる位置に配置し、アプリを再起動して両方の位置・表示状態が
  独立して復元されることを確認する (SC-005)
- (可能であれば) モニタ B を一度取り外して同じ端子に再接続し、設定が保持されていることを確認する
  (research.md #2 のモニタ識別方式の検証。別の端子へのつなぎ直しは下の項目、research.md #20)
- アプリを終了し、モニタ A のケーブルを GPU の別の端子につなぎ直してからアプリを起動する。モニタ A の
  ウィジェットが、つなぎ直す前と同じ表示/非表示・位置で表示されることを確認する (FR-040、
  Acceptance Scenario 4)
  - `%APPDATA%` の `settings.json` で、モニタ A のキーの端子ごとの部分 (`UID` の番号など) が
    変わり、古いキーが残っていないことを確認する (research.md #20 の 2 つ目の前提の確認)
- 同じことを、アプリを起動したままケーブルをつなぎ直して行い、ウィジェットがつなぎ直す前と同じ
  位置に出ることを確認する
- 以前のバージョン (v1.2.x) で使っていた `settings.json` のまま、このバージョンを起動し、各モニタの
  ウィジェットがアップデート前と同じ表示/非表示・位置で表示されることを確認する (Acceptance Scenario 6)
- 同じ型番のモニタ 2 台の場合 (Acceptance Scenario 5・7 と、台数が変わる Edge Cases) は、手元に同じ型番の
  モニタがないため実機では確かめない。単体テスト (tasks.md T118) でのみ確かめており、実機では未確認
  (plan.md の Complexity Tracking)

#### モニタごとの設定 (FR-038・FR-041・FR-042、2026-10-01 追加、issue #53・#17)

画面とメニューの形は [`ui-per-monitor-settings.md`](./ui-per-monitor-settings.md) と
[`contracts/context-menus.md`](./contracts/context-menus.md) に照合する。

- 以前のバージョン (v1.2.x) の `settings.json` を残したまま、モニタ A・B をつないでこのバージョンを起動する
  - 両方のウィジェットが、アップデート前と同じ見た目・位置・位置ロック・最前面表示で表示されることを確認する (US4-6・US4-10)
  - `settings.json` のルートから `Appearance`・`WindowBehavior` がなくなり、各モニタの中に入っていることを確認する
  - 以前に保存されていて、今つながっていないモニタ (行ったことのある会議室のプロジェクターなど) のエントリが
    `"IsVisible": false` になっていることを確認する (US4-6)。手元にそうしたモニタの設定がなければ、
    起動する前に `settings.json` の `Monitors` に、つながっていないモニタのエントリを手で 1 つ足しておく
- モニタ B のウィジェットを右クリックして「詳細設定...」を開き、「編集するモニター」がモニタ B になっていることを確認する (US4-13)
  - タスクトレイから開いたときは、プライマリモニタになっていることを確認する (US3-13)
  - モニタ A を選んでいる状態で、モニタ B のウィジェットから「詳細設定...」を選ぶと、モニタ B に切り替わることを確認する。
    タスクトレイから選んだときは、選択が変わらないことを確認する (FR-042)
- モニタ A を選んでフォントサイズ・文字色・日付の表示・背景を変え、モニタ A のウィジェットだけが変わることを確認する (US4-8、SC-009)
  - モニタ A のフォントの種類を変えてから、フォントを一度も変えていないモニタ (既定値) を選び、フォントの欄が空欄になることを確認する。
    前のモニタのフォントが残って見えないこと (tasks.md T143)
- モニタ A のウィジェットの右クリックメニューで位置ロックを ON にし、モニタ A は動かせず、モニタ B は動かせることを確認する (US4-12・US4-17)
  - 最前面表示も、モニタ A だけが切り替わることを確認する
- アプリを再起動し、モニタごとの見た目・位置ロック・最前面表示が復元されることを確認する (US4-9・US4-18、SC-005)
- 詳細設定でモニタ B を選び、「このモニターに表示する」を OFF にする
  - モニタ B のウィジェットが消え、選択肢が「モニター 2 (非表示)」のように変わることを確認する (US4-16)
  - モニタ B のウィジェットから開いた詳細設定画面が、ウィジェットが消えた後も開いたままであることを確認する
  - ON に戻すと、元の見た目・位置で表示されることを確認する
- 詳細設定画面を開いたまま、モニタ B のケーブルを抜く
  - 選択肢からモニタ B が消えることを確認する。モニタ B を選んでいた場合は、プライマリモニタに切り替わることを確認する (US4-11・US4-16、issue #17)
  - ケーブルを戻すと、選択肢にモニタ B が戻ることを確認する。モニタ A を選んでいた場合は、選択がモニタ A のままであることを確認する (FR-042)
- 一度もつないだことのないモニタ (会議室のプロジェクターなど) をつなぎ、時計が表示されないことを確認する (US4-14)
  - アプリを起動したままつなぐ場合と、つないでからアプリを起動する場合の両方で確かめる
  - そうしたモニタがなければ、アプリを終了して `settings.json` からそのモニタのエントリを消し、起動してから確かめる
    (起動したままつなぐ場合は、エントリを消した後、モニタを外した状態で起動し、起動したままつなぐ)
  - 詳細設定でそのモニタを選ぶと、「このモニターに表示する」が OFF で、見た目が既定値であることを確認する
- `settings.json` を別名に退避してからアプリを起動し、プライマリモニタだけに既定の見た目で表示されることを確認する (US4-15)。
  確認後は、退避した `settings.json` を戻す
- タスクトレイの常駐アイコンを右クリックし、「詳細設定...」「自動起動」「終了」だけが並び、「自動起動」に今の ON/OFF の
  チェックが付いていることを確認する (US3-14)
  - 「自動起動」を選ぶと、スタートアップフォルダのショートカットが作られる (消える) ことを確認する (US1-4)
  - 詳細設定画面に「モニター・起動」タブがないことを確認する

### DPI 混在環境の確認 (可能であれば)

- モニタごとに異なる拡大率(例: 100%と 150%)を設定しているマルチモニタ環境、または

## 既知の制約の確認 (任意)

- DirectX 排他フルスクリーンモードのアプリ上ではウィジェットが隠れる場合がある
  (research.md #9 の既知の制約であり、不具合ではない)
- 背景透過度 100% の状態でも、ドラッグ・右クリックメニュー操作ができることを確認する
